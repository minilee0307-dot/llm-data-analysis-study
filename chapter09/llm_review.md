# Chapter 09 실제 LLM 검토 기록

- 검토일: 2026-11-02
- 도구: Codex 독립 검토 에이전트
- 고객 원본 행·ID·이름·연락처를 제공하지 않았다.
- 요청 시점에는 모델 성능을 제공하지 않았으며, 다음 응답은 코드 실행 결과가 아닌 계획 검토다.

## Prompt 요약과 Safe Context

공식 공통 합성 데이터150고객·100상품·300주문·764상세로 전체 주문의 order_total을 예측한다. Train은244건(2025-07-09~2026-04-13), Final Test는56건(2026-04-14~2026-07-08)이라는 날짜순 분할 요약을 제공했다. 교육용 시점은 고객 프로필·예정 결제수단·달력 정보는 알고 상세 수량·단가는 아직 조회하지 않은 때다. 허용 Feature6개와 금지 Feature11개, Train Fold Pipeline 전처리, 고정 후보 DummyMean·Linear·RF300/min_leaf5/seed42, 고유 날짜 TimeSeriesSplit5fold, 비Baseline CV MAE 최소 모델 고정 후 마지막 Test 평가 계획을 전달했다.

시점 가정의 맹점, CV와 평가의 공정성, MAE/RMSE/R² 해석, 오차의 관찰과 원인 가설, 사용·수정·보류 후보를 요청했다. 선택 모델과 Final Test 점수는 아직 제공하지 않았으며 숫자나 원인을 만들지 말라고 요청했다.

## 실제 응답

제공된 내용은 분석 계획으로 검토했다. 실제 코드·CV·Final Test 결과를 확인하지 않았으므로 선택 모델이나 성능 개선 여부를 단정할 수 없다.

1. 예측 대상은 취소·환불을 포함한 전체 주문의 상세 금액 합이다. 이를 실제 결제액이나 매출로 부르지 않아야 한다. 주문별 Target을 원본 상세에서 별도로 계산하고, 주문 누락·중복·미연결과 합계 일치를 확인하는 계획은 적절하다.

2. Feature 6개는 제시한 교육용 시점 가정 아래에서 사용 가능하다. 다만 예정 결제수단이 실제로 그 시점에 수집되는지, 나이·도시가 과거 주문 당시 값인지 확인되지 않았다. 현재 프로필을 과거 주문에 붙였다면 시간상 누수 위험이 남는다. 가정과 한계를 명시하고 실제 서비스에서는 수집 시점이 검증된 값만 사용해야 한다.

3. 날짜 단위 분할과 Train 내부의 날짜 단위 TimeSeriesSplit은 같은 날의 정보가 경계를 넘는 문제를 줄인다. 결측 보완·스케일링·인코딩을 각 Fold의 Train에만 fit하는 원칙도 유지해야 한다. 동일 고객이 양쪽에 존재할 수 있으므로 결과가 신규 고객 예측 성능까지 보여 준다고 해석하지 않는다.

4. 후보와 선택 규칙을 미리 고정하고 Train CV의 평균 MAE로 비Baseline 모델을 선택한 뒤 Final Test를 한 번 평가하는 순서가 적절하다. CV 표준편차도 함께 제시하되 Test 결과를 보고 모델·Feature·분할을 바꾸지 않는다. 비Baseline 후보가 선택되더라도 Baseline보다 유용하다는 뜻은 아니다.

5. MAE는 평균 절대 오차를 원 단위로 나타낸다. RMSE는 큰 오차에 더 큰 영향을 받는다. R²의 비교 기준은 해당 평가 구간의 실제값 평균이며, Dummy가 학습한 Train 평균과 다르다. 따라서 Train 평균을 예측한 Baseline의 Test R²도 음수일 수 있다. MAE 개선율은 `(Baseline MAE−선택모델 MAE)/Baseline MAE×100`이며 음수면 악화다.

6. 큰 오차 사례의 실제값·예측값·잔차는 관찰이고, 정보 부족이나 분포 차이는 추가 검증할 가설이다. 상세 정보를 사후 진단에 참고하더라도 이번 예측 시점의 Feature로 다시 넣으면 안 된다. 내부 ID 파일의 Git 제외뿐 아니라 Notebook 출력과 공개 보고서도 점검해야 한다.

적용 판단은 Target·관계 검증, Pipeline, 날짜 분할, 선택 고정 절차는 **사용**, Feature의 시점 가정과 지표 설명은 **명확히 수정하여 사용**, 실제 배포 가능성·오차 원인의 단정은 **성능 및 추가 자료 확인 전 보류**가 적절하다.

## 실제 반영과 한계

Target·관계·날짜 분할·Pipeline 검증은 실제 실행으로 사용했다. 시점 가정과 R²의 Test 평균 기준은 답안에 명확히 적었다. Train CV에서 비Baseline 최저 MAE인 Random Forest를 고정했고, Baseline CV가 더 좋았다는 결과도 남겼다. Final Test에서 개선율−3.47%로 나와 현재 모델의 사용은 보류했다. 이 결과를 보고 모델·Feature·분할을 다시 선택하지 않았다. 필수 재실행은 고정한 같은 절차의 재현이며 새로운 모델 선택이 아니다. 작성·실행·독립 검토와 문장 정리에는 Codex의 도움을 받았다.
