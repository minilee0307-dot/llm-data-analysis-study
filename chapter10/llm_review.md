# Chapter 10 LLM 검토와 반영 기록

## 요청과 응답

별도 Codex 검토에 공식 가이드, 분석 계획, 원본 집계값만 제공했다. 행 단위 데이터와 고객 정보, 최종 Test 지표는 전달하지 않았다. 검토는 모델 학습이나 성능 탐색 없이 진행했다.

> 주문 접수 후 결과 확정 전 예측, 완료 184건·취소 64건·환불 52건, 이진 대상 중 가입일 역전 45건을 전제로 분석 계획을 검토해 달라. 60/20/20 층화 분할, Train 전처리, Validation에서 모델과 Threshold 고정, 공개 예측 익명화, FP/FN 해석에서 사용할 것, 수정할 것, 보류할 것과 확인 방법을 제안해 달라.

| 판단 | 제안 요약 | 실제 확인과 적용 |
| --- | --- | --- |
| 사용 | 취소를 양성으로 두고 Dummy 정확도와 취소 탐지 지표를 같이 비교 | 원본 상태 집계와 분할별 클래스 수를 확인했다. Validation에서 Dummy 정확도 0.7400, 취소 Recall과 F1은 0이었다. |
| 사용 | Validation에서 모델과 Threshold를 고정한 파일을 남기고 혼동행렬에서 지표 재계산 | 선택 설정을 먼저 저장하고 Final Test 뒤 내용이 같은지 검증했다. 혼동행렬 TN 24, FP 13, FN 7, TP 6에서 네 지표를 재계산했다. |
| 수정 | 가입일 역전 행의 날짜 차이를 0으로 바꾸거나 삭제하는 대신 입력의 시간 관계를 점검 | 공식 예제는 이진 분류 범위의 역전 45건에서 중단됐다. 해당 파생변수만 제외하고 248건과 원본 날짜를 유지했다. |
| 수정 | `line_total`의 출처를 명확히 구분 | 공통 원본에는 `line_total`이 없다. 전처리가 만든 값과 원본 `quantity × unit_price`의 별도 계산이 764행에서 일치했다. |
| 보류 | 무작위 분할 결과로 미래 운영과 인과관계를 결론짓는 해석 | Train과 Test가 고객 26명, 주문 날짜 17일을 공유했다. Final Test에서 취소 13건 중 6건을 탐지했고 정상 주문 13건도 표시해 운영 사용을 보류했다. |

서로 다른 구현으로 원본 주문별 집계, 분할, Train 전처리 통계, Validation 비교와 임계값, Final Test의 혼동행렬과 지표를 확인했다. 두 구현의 결과 대조는 Notebook의 검증 근거에 정리했다.
