# Chapter 08 실제 LLM 검토 기록

- 검토일: 2026-10-27
- 도구: Codex의 독립 검토 에이전트
- 고객 이름·원본 ID·이메일·연락처·개별 고객 행은 제공하지 않았다.
- 다음 응답은 검증 방법의 제안이다. 제안에 숫자가 언급되어 있다는 이유로 검증 완료로 처리하지 않았다.

## 전달한 Prompt 요약과 Safe Context

Chapter 08의 질문·검증 계획을 검토해 달라고 요청했다. 공개 수업용 합성 데이터 4개를 원본부터 다시 전처리하며, 기존 clean 행 수는 고객150·상품96·주문298·상세724이다. 기준일은 앞 장과 비교하기 위해 2026-10-08로 고정한다. completed 전체 상세는430행·137,335,000원이고, 날짜 결측6행·1,903,000원과 기준일 이후3행·909,000원을 공통 분석 범위에서 명시적으로 제외한다. 예상 범위는421상세·상세 보유175주문·조건 충족176주문·134,523,000원·구매고객96명이다. 이 수치는 입력한 요약이며 새 실행에서 다시 확인한다고 설명했다.

질문은 카테고리별 금액, 월별 금액·주문 수·평균, 익명 상위 고객의 금액·횟수로 정했다. 일부 상세가 격리된18주문을 제외하면157주문·120,972,000원이며, 패션 금액32,940,000원·비중24.49%, 월14개, Top10금액41,420,000원·30.79%라는 기존 요약을 제공했다. 광고·원가·재고 데이터는 없다고 밝혔다.

요청한 검토 항목은 ①범위의 맹점 ②원본 CSV 기준 독립 검산 ③날짜 FAIL과 처리 정책 ④그래프 선택과 실제 artist 대조 ⑤관찰·해석·개인정보 ⑥사용·수정·보류 제안이다. 원본을 읽지 않았는데 읽었다고 하거나, 새로운 원인·결과를 만들지 말라고 요청했다.

## 실제 응답

아래 수치는 제공받은 요약값이며, 원본 파일을 직접 검증한 결과가 아닙니다. 다음은 실제 실행으로 확인할 검토 제안입니다.

1. **분석 범위**
질문 3개는 적절합니다. 다만 조건을 통과한 176주문과 유효 상세가 있는 175주문을 구분하고, 평균 주문금액의 분모를 명시하세요. 금액은 남은 유효 상세의 합계이므로 원래 청구총액·순매출·이익으로 해석하면 안 됩니다. 일부 상세가 격리된 18주문을 제외한 민감도도 비교하되 총액만 보고 순위가 유지된다고 단정하지 마세요.

2. **독립 검산**
같은 병합 결과를 여러 번 집계하는 것만으로는 부족합니다. 원본 CSV를 별도로 읽어 전처리의 채택·격리 규칙을 재현하고, 주문 ID 사전과 원본 상세를 연결해 `Decimal(quantity) × Decimal(unit_price)`를 합산하세요. 채택 행 수·주문 수·제외 사유별 건수와 금액도 함께 대조해야 합니다.

3. **날짜 FAIL 처리**
초기 137,335,000원과 날짜 결측을 빠뜨린 월별 합계의 차이 1,903,000원을 먼저 FAIL로 남기세요. 이후 결측 6행과 미래 후보 3행의 제외 정책·영향을 공개하고, 공통 범위 134,523,000원으로 모든 집계를 다시 계산하세요. 최종 PASS는 선택한 분석 범위의 검증이며 원본 날짜를 복원했다는 뜻은 아닙니다.

4. **그래프 검증**
카테고리 막대는 범주 비교, 월별 선은 시간 변화, 익명 고객 가로 막대는 순위 비교에 적합합니다. 실제 막대 높이·너비와 선의 날짜·금액을 집계표의 개별 값과 대조하세요. 축 단위·정렬·0축을 확인하고 누락 월을 임의의 0으로 채우지 마세요.

5. **해석과 개인정보**
패션 금액 비중이나 Top10의 반복 구매는 관찰입니다. 선호·광고 효과·충성도의 원인은 아닙니다. 공개 CSV·Notebook 출력·그래프 모두에서 이름·연락처·원본 고객 ID를 제거하고 순위 라벨만 남기세요.

6. **적용 판단**
세 질문과 독립 검산은 사용하고, 날짜 처리와 주문 수 정의는 수정 후 사용하세요. 원인·수익성·미래 고객가치 결론은 보류하세요. 전체 재실행 후 저장 파일을 다시 읽어 같은 값과 Validation 결과가 나오는지 확인하세요.

## 실제 반영 여부

Notebook의 LLM 활용 표에서 제안별 사용·수정·보류와 실제 실행 근거를 연결했다. 날짜 처리 전 FAIL을 지우지 않고 최종 분석 범위를 정한 후 다시 검증했다. 원본 CSV를 별도로 읽는 Decimal 재집계는 사용하되 전처리의 격리 행 번호를 공유하므로 행 선택 전체가 독립적이지 않다는 범위를 명시했다. 저장 고객 CSV 재읽기, 실제 그래프 값 대조와 전체 스크립트 재실행 결과는 Notebook 출력으로 확인한다. 코드 작성·실행·검토와 문장 정리에는 Codex의 도움을 받았다.
